# Progress log

One entry per finished part. Three lines minimum: the business rule, the stack concept, what surprised you.

## Part 01 — Setup
- Business: a clinic day is book → check in → examine → note and vaccine → prescription → invoice and payment → recall. Half the day is walk-ins; most prescriptions go to a pharmacy; discounts are negotiated at the desk. Everything the software holds must trace to `docs/domain/clinic-day.md`.
- Stack: Spring Boot 4.1 parent POM supplies the BOM and plugin defaults; only MapStruct, springdoc, and the frontend plugin are pinned. Flyway runs before Hibernate and `ddl-auto=validate` makes the migration the schema of record. `frontend-maven-plugin` builds Angular into `static/` so one jar serves everything on one port.
- Surprise: the Angular CLI blocks a non-interactive build with an analytics prompt; had to disable it in `angular.json` (commit `f57d88b`). Also Testcontainers needs Docker in CI, so the runner choice matters.

### Self-check
- Boot parent POM gives: managed versions for every Spring, Hibernate, Flyway, Testcontainers, Lombok, and driver dependency (the BOM); default plugin configuration (compiler from `java.version`, surefire/failsafe, `spring-boot-maven-plugin` repackage); resource filtering. We pin only what the BOM does not manage.
- Angular is served from the jar so there is one artifact, one port, one TLS endpoint, no CORS, and no second web server to run on the VPS. Cost: every `./mvnw package` rebuilds Angular.
- Claude reads `CLAUDE.md` at the repository root at the start of every session, plus `openspec/config.yaml` context when an OpenSpec command runs.


## Part 02 — Practice
- Business: a practice is one clinic business and the tenant root; country decides currency, locale, timezone, and regulatory framework, and an unmapped country is an error, never a default. Status starts `trial` and only the platform changes it. Identity columns (address, phone, VAT number, tax rate) exist for printing invoices and certificates.
- Stack: Flyway migration first, entity second, `ddl-auto=validate` as the referee. Postgres generates the id (`uuidv7()`, time-ordered) so the entity has `@Id` without `@GeneratedValue`. DTO record plus MapStruct keeps the API shape independent of the table. `@SpringBootTest` with Testcontainers starts the whole context against a real Postgres 18, runs Flyway and the seed, then hits the HTTP port.
- Surprise: `validate` rejected `char(2)` on the first run. Postgres reports it as `bpchar` (JDBC `CHAR`) while a Java `String` defaults to `VARCHAR`; the fix is `@JdbcTypeCode(Types.CHAR)` on the entity, not a migration change. Also Hibernate 7 moved `PostgreSQLEnumJdbcType` to `org.hibernate.dialect.type`. Generated Angular names needed `@Tag(name = "practice")` and `@Schema(name = "Practice")` to avoid `PracticeControllerApi` and `PracticeDtoDto`.

## Part 03 — Users, roles, and login
- Business: one role per user decides what they manage; a separate `is_veterinarian` flag decides clinical acts, because the owner of a one-doctor clinic is admin and vet at once. Staff log in with their phone (any Egyptian shape) or their email; phone is required, email optional, both unique per clinic. Onboarding and reset have no email: the admin hands over a temporary password and the user must change it first. Revocation is immediate through `session_version`. Login is rate limited, never locked.
- Stack: stateless HS256 JWT via Spring Security's Nimbus encoder/decoder; `JwtFilter` loads the user row on every request and rejects inactive or version-mismatched tokens; `@EnableMethodSecurity` with `hasRole` on services and `@access.isVeterinarian()` for the flag; Bucket4j in memory for the login buckets; `FilterRegistrationBean.setEnabled(false)` so security-chain filters are not double-registered by Boot.
- Surprise: `@Transactional` on a `OncePerRequestFilter` breaks Tomcat startup (`logger` is null on the CGLIB proxy). An `@Id` without a generator makes Hibernate refuse a null id on insert; `@GeneratedValue(IDENTITY)` on Postgres uses `INSERT … RETURNING`, so the `uuidv7()` default still wins. Springdoc marks record components optional unless annotated, so the generated TypeScript had `token?:`; `@Schema(requiredMode = REQUIRED)` fixed the response DTOs, and `stringEnums: false` gives literal unions instead of TS enums.

## Part 04 — Tenant boundary and audit log
- Business: two clinics on one database never see each other's rows, and every change is attributable. Both are promises enforced by Postgres, not by service code: RLS on every table with `practice_id`, forced so even the owner is subject to it; an audit trigger on every tenant table and on the practice row, stripping `password_hash`; the application role cannot change `practices.status`, edit or delete audit rows, or call the trigger functions.
- Stack: two database roles (`qvety_owner` for Flyway, `qvety_app` for the app, `NOBYPASSRLS`). A `TenantTransactionManager` (subclass of `JpaTransactionManager`) writes `app.practice_id` and `app.user_id` with `set_config(..., true)` right after every transaction opens, so services, repositories, and the JWT filter's lookup all carry the tenant; no tenant and no `SystemContext` throws before any statement. `tenant_table_setup(regclass)` is the one call each later migration makes per table. `TenantIsolationIT` derives the expected table set from the catalog, so a forgotten table fails CI.
- Surprise: login cannot work under RLS without an exception, since no tenant is known yet; `login_lookup(email)` as a `SECURITY DEFINER` function is that single, explicit exception. The column-level grant caught Hibernate's full-row `UPDATE` on `practices` (it rewrites `status` too); `@DynamicUpdate` plus `updatable = false` fixed it, and the grant did exactly what it was for. `SystemContext` had to live in `tenant`, not `platform`, because `auth` needs it; part 11 fences callers with ArchUnit instead. Testcontainers `@ServiceConnection` cannot express two users, so the test config provides `JdbcConnectionDetails` (app) and `FlywayConnectionDetails` (owner) beans.

## Part 05 — Arabic and RTL
- Business: Arabic by default, switchable per user, and the choice follows the person across devices because it lives on the user row. UI strings and coded labels (roles, statuses) are translated; anything the clinic types (names, notes, service names) is never translated. Phone, email, license numbers and other Latin values stay left-to-right inside an Arabic page. Backend messages come back in the user's language.
- Stack: Transloco with `ar.json`/`en.json` under `web/src/assets/i18n`; one `LocaleService` that sets Transloco, `<html lang dir>`, NG-ZORRO i18n, and a device fallback in `localStorage`; the CDK `[dir]` directive on the app root is what NG-ZORRO 22 components read. `Accept-Language` from the interceptor, `MessageSource` with `messages_ar/en.properties`, Bean Validation messages through the bundle, and one `ApiError` shape (`code`, localized `message`, `fields`) that the forms display. Theme wired: `ng-zorro-antd.less` + `qvety-theme.less`, `qvety-tokens.css`, self-hosted IBM Plex via `@fontsource`, favicon/manifest.
- Surprise: NG-ZORRO 22 has no `direction` config key; direction comes only from CDK `Directionality`, so a `[dir]` binding on the root is required. The SPA forward regex swallowed `/assets/i18n/ar.json` (no dot in the first segment); a `PathResourceResolver` that serves real files and falls back to `index.html` replaced it. Jackson 3 refuses `null` into a primitive boolean, so a missing `veterinarian` field was a 400 from the parser, not from validation. jsdom under the Angular test builder has no `localStorage`; the spec shims it. A headless Firefox walkthrough (Playwright, in the scratchpad, not in the repo) found three more: springdoc emits `*/*` for responses so the generated client read bodies as text (`produces = application/json` on every controller fixed it); `DatePipe` needs the registered locale id (`ar-EG`), not the short language; NG-ZORRO's vertical form labels are hard-coded `text-align: left` even under `ant-form-rtl` (one `text-align: start !important` rule).

## Part 06 — Clients
- Business: a client is the person who pays; the name is one free-text chain, never first/last; a phone or an email is required; no national id column by design; archived, never deleted; duplicates (same phone in either column, same name after case fold) warn and never block, because two family members legitimately share one phone.
- Stack: `TenantEntity` mapped superclass (Postgres-generated id, `practice_id` from the tenant context on insert, `@Version`, timestamps); `User` moved onto it. `DomainException` with bundle keys, `stale_update` 409 on an explicit version check (`If-Match` header), `bad_sort` 400. Spring Data `PagedModel` (`serialization-mode: via_dto`) as the one page shape. Angular generic `list-page` (server paging, sort, debounced search) and `form-page` (config-driven, server field errors on controls); `features/clients` uses both, plus a `history-tab` over the audit log that any later detail page reuses.
- Surprise: Flyway runs repeatable seeds in description order, so `R__dev_clients` ran before `R__dev_practice` and hit the foreign key; seeds now carry numeric prefixes. Springdoc builds operationIds from Java method names, so `list`/`get`/`create` across controllers became `list1`, `create1` in the generated client; controller methods are now named per resource (`listClients`). `RestClient.uri(String)` re-encodes `%2B`, so a `+` in a test query needs a URI template variable.

## Part 06b — Mobile shell (retrofit)
- Business: staff use their own phones more than the desk PC, standing, one-handed. The phone is a different set of tasks, not a narrow desktop: stacked rows, a thumb-reachable bottom bar, 44 px targets, one action per screen title, and never a bottom nav and an action bar on the same screen.
- Stack: `ViewportService` (`isPhone` from `matchMedia`, `actionBarPresent`, sidebar state); one shell with two structures (phone column with strip, scroller, bottom nav, "Me" sheet; desktop strip plus 196 px collapsible sidebar); `title-bar` and `action-bar` components used by every screen; `list-page` renders stacked rows with column roles and load-more on phone, the table on desktop; `form-page` puts Save in the action bar; phone CSS for 16 px / 52 px inputs; login as the screen-13 bottom sheet.
- Surprise: `:host-context([dir='rtl'])` in a component's scoped stylesheet does not reach icons inside other components, so the mirror rule for directional icons must be global. The Playwright walkthrough with structural assertions (overflow, nav/bar exclusivity, no table on phone, min input and button heights) at 390, 360, and 1280 in both languages is now the definition of "checked on phone".

## Part 07 — Arabic search and Egyptian phone numbers
- Business: the desk types the same person differently every time (`أحمد`/`احمد`, `فاطمة`/`فاطمه`, with or without tashkeel) and the same phone in several shapes. Search, the duplicate warning, and sorting by name run on a folded copy of the name and on E.164 phones; the card always shows what was typed. A phone that does not parse as Egyptian is refused on the field, never guessed. Rules in `docs/domain/search-and-normalization.md`.
- Stack: `TextNormalizer` (pure, table-driven test) and the part 03 `PhoneNormalizer`; `V6__search.sql` adds `pg_trgm`, the three stored columns with a rough SQL backfill, a trigram GIN index and btree indexes, and drops the part 06 raw-column indexes. `ClientService` folds on every save and picks the search branch (blank, phone, name); the name branch is a native query on `ILIKE` or the `%` trigram operator ordered by `similarity()`, the phone branch JPQL on both E.164 columns; `sort=fullName` is rewritten to the folded property so the API does not change. `DomainException` gained an optional field so a service rule can land in `ApiError.fields` like bean validation.
- Surprise: `similarity(col, q) > 0.3` cannot use the GIN index; the `%` operator can, with the same 0.3 default from `pg_trgm.similarity_threshold`. A native query with a sorted `Pageable` gets the sort appended after its own `ORDER BY`, so the name branch passes an unsorted page request. `./mvnw verify` without `clean` kept stale seed files in `target/classes` (old `R__dev_*` names) and the local database still held their history rows; both are gone now. The dev seed must fill the folded columns by hand because it inserts below the service.

## Part 06c — Archived clients reachable, phone required
- Business: an archived client is not gone; a desk that archived by mistake, or a returning owner, needs a way back without a bookmarked URL. A client without a phone is a client the clinic cannot call or WhatsApp, and the recall feature that pays for the subscription runs on the phone, so the phone is required and email is a bonus.
- Stack: one boolean query parameter threaded through the three read paths (`findAll` vs `findByArchivedAtIsNull`, native name search, JPQL phone search) instead of a second endpoint; the unarchive endpoint mirrors archive and is idempotent. Angular `list-page` gained a projected filter slot (`list-extra`, `list-extra-phone`) and a public `reload()`; the clients list projects an `nz-switch` and adds a `tag` column for the archived state.
- Surprise: replacing the derived `findByArchivedAtIsNull` with a JPQL query turned `sort=nope` from a 400 `bad_sort` into a Hibernate `UnknownPathException` 500; derived queries validate sort properties, hand-written JPQL does not. A DTO returned inside the same transaction carries the pre-flush `version`, so a test that edits right after an action must re-read the row first.

## Part 08 — Patients
- Business: the patient is the animal and belongs to one client; name, species, and owner are required, breed is free text because clinic breed lists never agree. A patient is transferred (old owner kept) or marked deceased, never deleted; a deceased patient stays with the owner who lost it. Allergies and weights are evidence: a wrong allergy is retracted with a reason, a wrong weight is voided with a reason, and the row stays visible. Arabic sex labels say معقّم, not مخصي.
- Stack: `V8__patients.sql` with the composite `(client_id, practice_id)` FK so a cross-practice link fails at the database, Postgres enums through `@JdbcType(PostgreSQLEnumJdbcType.class)`, `@ManyToOne(fetch = LAZY)` with `default_batch_fetch_size`, `JpaSpecificationExecutor` for the list filters, and two small `SECURITY DEFINER` guard triggers (`patient_allergy_guard`, `patient_weight_guard`) that allow only the retract/void columns to change. Angular: nested route `/clients/:id/patients/:pid`, detail with tabs, Edit as the title-bar action, Transfer on the owner row, Mark deceased beside Edit on desktop and in the phone action bar.
- Surprise: `(click)="void(w)"` in an Angular template is the JavaScript `void` operator, not a method call; nothing fires and nothing errors. Editing an uncommitted migration means dropping the local schema (`Migration checksum mismatch for migration version 8`); Testcontainers never noticed because it starts clean. The first placement of Edit and Archive under the tabs read as tab actions; actions now sit next to the thing they act on.

## Part 03b — Login when the same phone exists at two practices
- Business: a vet or receptionist can work shifts at two clinics, and each clinic creates its own user row for them with the same phone. Login runs before any practice is known, so it must try every row: their own password at each clinic logs them into that clinic; the same password at both asks which clinic; a wrong password reveals nothing. The picker is the pattern Slack and Notion use after the password, not before.
- Stack: `AuthService.login` checks every active row from `login_lookup()` in practice-id order and collects the matches; `V7__login_practices.sql` adds the second definer function, id and name only, called only with ids that just matched; `LoginResponse` is one record with nullable `token`/`user` or `practices`, and `LoginRequest` gains an optional `practiceId` that narrows, never widens. Angular shows the practices as 44 px rows under the inputs, locks the identifier, and posts again; the walkthrough at 1280, 390, 360 in both languages checks overflow, row height, the mirrored chevron, and the second request body.
- Surprise: seeding a second user with the seed desk phone broke the part 03 phone-shape test (it got the picker), so that user starts inactive and the 03b tests switch it on and off. The rate-limit reset is asserted through the `LoginRateLimiter` bean with a fake IP, because ten real failures would spend the shared 127.0.0.1 budget for every other test. `sessionStorage` in the Angular unit tests carries the token from one test to the next, so the login spec clears it first. The generated client hard-codes the spec host into `api.base.service.ts`; generating from a second backend on :8081 needs that file reverted.

## Part 09 — Reference data (rooms, appointment types, services)
- Business: three small lists a practice configures for itself, and the only tables a generic CRUD is allowed to serve. A row is reference data when it is only ever picked from a list; anything with a status that moves (invoices, appointments, visits) is not, however small it looks. Rows are deactivated and reactivated, never deleted, because appointments (part 10) and invoice lines (part 14) point at them, and "make a new one with the same name" splits history instead of fixing it. A new Egyptian clinic opens with Arabic rooms, visit types, and a price list in EGP instead of an empty screen. Rules in `docs/domain/reference-data.md`.
- Stack: `V9__reference_data.sql` with a unique index on `(practice_id, lower(name))` per table covering active and inactive rows alike, and `UNIQUE (id, practice_id)` ready for the part 10 and part 14 composite foreign keys. One `ReferenceEntity`, one `ReferenceRepository` using `#{#entityName}` so a single JPQL query serves three tables, one `ReferenceService` holding every rule, and three-line controller subclasses; the service currency is copied from the practice row and is not a request field. The catalog is plain SQL with a `:practice_id` parameter applied by `StarterCatalogSeeder` (part 11 calls it; `R__050_dev_catalog.sql` fills the dev practice until then). Angular: one config object per entity drives one list and one form, so a fourth entity is a migration, an entity, a config object and a route.
- Surprise: three controllers inheriting six methods from a generic base gave springdoc `activate`, `activate1`, `activate2` — names that follow controller scan order, which is not stable; an `OpenApiCustomizer` now names reference operations from their own response schema (`activateRoom`). `<ng-content select="[secondary-action]">` does not match nodes nested inside an `@if`, so the Activate/Deactivate pair had to become one button whose label and colour switch. `ddl-auto=validate` refuses a `char(3)` column mapped as a plain `String`: Postgres reports `bpchar`, and the entity needs `@JdbcTypeCode(Types.CHAR)` the way `Practice` already did.
