# Part 02 — Practice (the tenant)

## Business

A **practice** is one clinic business. It has a name, a country, a default currency, a locale, a timezone, and a status. Every other record in the system will belong to a practice.

Rules to confirm and write down in `docs/domain/practice.md`:
- Country decides currency, locale defaults, and regulatory framework. Egypt: `EG`, `EGP`, `ar-EG`, `Africa/Cairo`.
- An unmapped country is an error at creation time, not a default to another country's rules.
- Status starts as `trial`. Only the super admin changes it (part 11). Enforcement comes in part 03/11; for now it is just a column.
- The practice edits its own identity (name, address, phone, VAT number, tax rate). The super admin edits country, currency, and status. The edit endpoint arrives in part 03 once there is an admin role.
- Practice is a **platform table**: it has no `practice_id` of its own. It is read by the practice itself (its own row) and by the super admin (all rows).

## Design

Table `practices`: `id uuid pk default uuidv7()`, `name`, `country char(2)`, `currency char(3)`, `locale`, `timezone`, `status` (Postgres enum `practice_status`), `address`, `phone`, `vat_number` (nullable), `tax_rate_percent numeric(5,2)` (default 0), `trial_ends_at` (set at creation from the platform `trial_days` setting; part 11), `created_at`, `updated_at`. Check constraint that `country` is in the supported list (`EG` only for now).

The identity columns (`address`, `phone`, `vat_number`, `tax_rate_percent`) exist for print: invoice header (part 14) and vaccination certificate (part 13). A clinic registered for VAT puts its number on every invoice; most small clinics are not registered and leave it empty with `tax_rate_percent = 0`. The logo comes in part 13 with object storage.

Endpoint: `GET /api/v1/practice` returns the caller's practice. No auth yet; for this part, take the practice id from a header `X-Practice-Id`. This is temporary scaffolding and is deleted in part 03. If you already know Spring Security, skip the header and do parts 02 and 03 as one; the hack exists only so the first end-to-end line has no auth in the way.

## Steps

1. Write the migration by hand. Ask Claude to review it for naming, types, and the enum.
2. `Practice` entity, `PracticeRepository`, `PracticeDto` record, `PracticeMapper`, `PracticeService`, `PracticeController`.
3. `db/seed/R__dev_practice.sql` seeds one practice for local use (`Neighborhood Vet`, `EG`, fixed uuid so later seeds can reference it). Not in `V1`: a migration runs in production and production has no demo clinic.
4. Test: start Testcontainers `postgres:18`, Flyway runs migrations and seeds (test profile), `GET /api/v1/practice` with the seeded id returns 200 and the name.
5. Angular: a page that calls the generated `PracticeService.getPractice()` and shows the name. This is your first end-to-end line.
